# SaaS Security Core & Row-Level Security Architecture

## Identity & Session Management

- **Minimal Global Identity Lookup (`auth_identities`):** Stores only `(email, user_id, tenant_id)` so login requests can resolve the tenant before activating PostgreSQL Row-Level Security on `users`. Password hashes and profile data never leave the RLS-protected `users` table.
- **Password Hashing:** Uses `bcrypt_sha256` via Passlib.
- **Rotating Refresh Tokens:** Each refresh token carries a unique `jti` stored as a SHA-256 hash in `refresh_sessions`. Presenting a refresh token revokes it and issues a new pair within a `SELECT ... FOR UPDATE` transaction.
- **Multi-Tab Grace Window:** If a refresh token is reused within 15 seconds of revocation (`REUSE_GRACE_SECONDS`), it is rejected as a benign concurrent tab refresh; reuse after 15 seconds triggers full revocation of all active sessions for that user (`auth.refresh_reuse_detected`).

## Transactional Tenant Context (`app.tenant_id`)

`set_tenant_context(db, tenant_id)` stores `tenant_id` in `Session.info` and executes `SELECT set_config('app.tenant_id', :tenant_id, true)`. A SQLAlchemy `Session.after_begin` event listener re-applies this transaction-local GUC on every subsequent transaction within the request, ensuring `COMMIT` statements never strip RLS protection and pooled connections are never polluted.

## PostgreSQL `ENABLE` + `FORCE ROW LEVEL SECURITY`

All tenant tables (`tenants`, `users`, `branches`, `customers`, `services`, `staff`, `resources`, `appointments`, `subscriptions`, `audit_logs`, `refresh_sessions`, `user_branch_access`, and the 6 schedule/break tables) enforce both `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`. The runtime database user (`agendavoice_app`) is configured with `NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT` and has no `BYPASSRLS` privilege.
