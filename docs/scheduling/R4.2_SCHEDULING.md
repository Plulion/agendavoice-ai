# Universal Scheduling Engine & Concurrency Model

## Temporal Model

- `branches.timezone` stores a validated IANA timezone (e.g., `America/Santiago`).
- Opening hours, closing hours, and breaks are stored as weekly local `TIME` entries (`weekday` `0` = Monday through `6` = Sunday).
- `appointments.starts_at` and `appointments.ends_at` are stored as UTC `TIMESTAMPTZ`.
- Total occupied interval = `services.duration_minutes + services.buffer_minutes`.

## Schedule Inheritance

Each branch defines a complete 7-day schedule (`branch_hours` and `branch_breaks`). Individual staff members (`staff_hours`) and physical resources (`resource_hours`) inherit their branch's schedule automatically until a custom 7-day schedule is configured for them. Once configured, custom schedules further restrict availability within the branch's operating window.

## Defense-in-Depth Double-Booking Prevention

1. **Deterministic Advisory Locks:** `POST /appointments` acquires transaction-level `pg_advisory_xact_lock` locks in sorted order for the target `(tenant_id, branch_id, staff_id)` and `(tenant_id, branch_id, resource_id)`.
2. **Half-Open Interval Validation:** Active appointments (`PENDING`, `CONFIRMED`) use `[starts_at, ends_at)` semantics so back-to-back appointments (`10:00–10:30` and `10:30–11:00`) never conflict.
3. **PostgreSQL GiST Exclusion Constraints:** Migration `0003` installs `ex_appointments_staff_no_overlap` and `ex_appointments_resource_no_overlap` using `EXCLUDE USING gist (tenant_id WITH =, staff_id WITH =, tstzrange(starts_at, ends_at, '[)') WITH &&)`. Even concurrent transactions from separate processes cannot double-book an asset.
